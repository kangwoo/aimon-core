## 1. 문제

`docs/backlog/` 의 등록부는 저마다 항목 수를 항목 밖에서 두 번 적는다 — 등록부 자신의 H1 표제
(`등록 항목 N건 (열림 X · 닫힘 Y …)`)에 한 번, `docs/backlog/README.md` 의 색인 표
(`| 항목 수 | 열림 | 닫힘 | 해소 |`)에 한 번. 둘 다 항목 제목에서 손으로 옮긴 사본이고, 어느 사본도,
그리고 항목 ID 가 한 번만 나오는지도 검사하는 것이 없다. 2026-09-10 에 두 브랜치가 각자
`llm-config-surface-open-items.md` 에 `## L-13` 을 더했고, git 은 두 항목 본문을 충돌 없이 합쳤다.
충돌한 것은 건수 두 줄뿐이었고, 그것이 누군가 알아챈 유일한 이유다. README 의 규칙 일곱(*요약표는
항목이 아니다*)과 그 날짜 문단들이 그 전의 건수 드리프트를 기록하고 있으며, 전부 사람이 읽다가 찾았다.
할 일은 표준 라이브러리만 쓰는 검사를 CI 에서 돌려 세 가지에 실패시키는 것이다 — 한 등록부 안에서
반복된 항목 ID, 항목과 어긋난 표제 건수, 항목과 어긋난 색인 행. 그것을 제목 모양·상태 단어·ID 접두어가
제각각인 등록부들에서 해내야 하고, 읽을 수 없는 등록부를 말없이 건너뛰어서는 절대 안 된다.

## 3. 접근

**ATX 제목 위의, 작고 완전히 명세된 읽기 문법.** 문법은 스크립트의 docstring 에 적고 `--self-test` 로
고정한다.

- 등록부는 문법을 따른다.
- 다른 모양으로 한결같이 쓰인 등록부 하나는 면제가 아니라 **선언된 읽기**를 받는다.
- 면제되는 등록부는 없다.
- 모든 발견은 exit 1 이다.

검사는 `docs/backlog/*.md` 의 `{상대 경로: 텍스트}` 위의 순수 함수다. 등록부마다 **항목 → (ID, 줄, 상태)**
를 읽고, 세고, 그 셈을 다음과 비교한다.

1. 같은 등록부의 다른 ID (중복),
2. 표제,
3. README 색인 행,
4. 다른 모든 등록부의 ID.

이것은 기존 검사들을 따른다.

- `check-translation-structure.py` 는 그럴듯한 읽기보다 좁고 적어 둔 패턴을 골랐고, 고정한 코퍼스에 대해
  읽기를 하나씩 바꿔 가며 그것을 고정한다.
- `check-translation-staleness.py` 는 고칠 몫이 그 파일을 쓴 사람에게 있는 발견(UNRESOLVABLE)을 실패시키고,
  다른 사람을 막게 될 발견은 실패시키지 않는다.
- 여기의 발견은 전부 앞의 종류다. 등록부나 색인을 고친 사람이 항목을 읽어서 맞출 수 있다.

## 4. 결정

### 4.1 제목 모양: 무엇이 항목인가

**결정: 문법.**

- **펜스 블록 밖의, 레벨 2 이상인 ATX 제목만 항목을 정의한다.** 펜스 처리는 `docs_tree.unfence` 로,
  `check-doc-links.py` 가 앵커를 계산할 때 쓰는 것과 같은 읽기이므로 두 검사는 무엇이 제목인지에 대해
  일치한다. 표, 인용 블록, 리스트 항목, 산문, 인라인 코드는 절대 항목을 정의하지 않는다.
- **ID 토큰:** `[A-Z]{1,3}-\d+` 뒤에 단어 경계 (그래서 `SBS-04b` 와 `P1-14` 는 ID 가 아니다).
- **항목 제목:** 텍스트가 **ID 런**으로 시작하고, 그 뒤에 공백과 `—` 또는 `·` 가 온다. ID 런은 ID 하나, 또는
  ` · ` 로 이어진 **같은 접두어의** ID 여럿이다. 런은 접두어가 다른 첫 ID 에서 멈춘다.
  - `B-7 · U-8 — …` 은 B-7 만.
  - `B-1 · P1-14 — …` 은 B-1.
  - `B-25 · SBS-04b …` 은 B-25.
  - `B-19 · B-20 · B-24 — …` 은 항목 셋.
- **항목 절:** 항목의 절은 같거나 더 얕은 레벨의 다음 제목까지, 또는 깊이와 무관하게 다음 항목 제목까지다.
- **읽지 않은 ID 제목 (발견):** 텍스트가 ID 토큰으로 시작하지만 항목 문법에 맞지 않는 모든 제목. 이것이
  아무에게도 알리지 않고 제목을 건너뛸 수 있는 유일한 길이므로, 조용해서는 안 된다.
- **선언된 번호 읽기, 등록부 하나 (`interrupt-open-items.md`).**
  - 항목은 N ≥ 1 인 레벨 2 제목 `## N.` 이다. `## 0.` 은 정정 기록이다.
  - 선언은 스크립트의 상수에, 이유와 함께 산다.
  - 선언은 스스로 무효가 된다. 파일이 없거나, ID 항목 문법에 맞는 제목이 하나라도 있으면 선언 자체가
    발견이다("선언을 지워라").

**왜 이 문법인가.** 열한 등록부 중 열은 이미 모든 항목을 ID 가 앞선 제목으로 쓴다. 예외는 스타터 §5 의
제목 셋과 인터럽트 등록부 전체다. 규칙은 한 줄로 말할 수 있고, 검사는 그 한 줄을 강제한다. 다음 작성자는
휴리스틱 묶음이 아니라 docstring 의 문법을 읽는다.

읽기를 선언하는 것과 제목을 고치는 것을 가르는 원칙:

- 등록부가 다른 모양으로 한결같이 쓰여 있고 **그 모양으로 인용될 때는 읽기를 선언한다.** 인터럽트 등록부의
  항목은 다섯 문서에서 번호로 가리켜진다.
  - `interrupt.md:566` 과 `:690`
  - `routing.md:355`
  - `inbox-collect-durability.md:47`, `:69`, `:81`, `:713`, `:721`
  - `architecture-review-open-items.md:739`
  - README 자신의 산문 ("2번", "3번")
- 제목 몇 개가 **자기 등록부의** 모양을 깨고, 그것을 가리키는 링크가 없고(§2.2), 그중 하나가 이미 B-21 에
  대해 틀려 있을 때는 **제목을 고친다.**

**기각한 대안:**

| 대안 | 기각한 이유 |
|---|---|
| **제목 어디에든 있는 ID** (휴리스틱) | 오늘 트리에서 가짜 중복이 난다: `#### 1차 전제 정정 (2026-08-05 낮) — B-20 의 문장은…` 은 B-20 자신의 묶음 안에 있고, `#### B-21 은 …` 은 B-21 을 되풀이한다. |
| **모든 등록부를 한 모양으로 정규화**, 열린 항목에도 상태를 명시 | `llm-config-surface`(15)와 `reasoning-delta-stream`(7)에서만 제목 편집 22건. 더 나쁜 것은, `L-16`…`L-19` 를 더하는 형제 작업들이 그 등록부의 지금 스타일(상태 없음)로 쓰므로 병합하는 족족 빨개진다는 것이다. 태스크는 그들을 특별 취급하는 것을 금지하므로, 검사는 관례를 있는 그대로 읽어야 한다. |
| **숨은 항목별 표식** (`<!-- item: L-13 state: 열림 -->`) | 상태의 세 번째 사본이고, 렌더된 페이지에서는 보이지 않는다. 규칙 일곱의 파생 뷰를 한 층 더 내린 것이다: 검사는 표식을 건수와 대조하겠지만, 독자가 실제로 보는 제목과 표식을 대조하는 것은 아무것도 없다. |
| **§5 용 두 번째 "라벨이 앞선 묶음 제목" 형태** (`<label> — B-19 · B-20 · B-24`) | 한 파일의 세 줄을 위한 두 번째 문법이다. `#### 1차 전제 정정 … — B-20 의 …` 같은 산문 소제목과 구별하려면 "ID 런 뒤에 아무것도 없다" 는 꼬리 규칙이 필요한데, 모르는 사이에 깨지기 쉽다. 그래도 B-21 을 해소로 읽는다(실측: 표제의 4 · 26 에 대해 해소 5 · 닫힘 25). 그러니 편집은 어차피 필요하다. |

### 4.2 상태 어휘

**결정.** 어휘는 `docs/backlog/README.md`(규칙 넷과 일곱, 색인 열)와
`docs/project/translation-glossary.md:157 ~ :162` 에서 가져온다.

| 항목 제목의 단어 | 세는 칸 | 출처 |
|---|---|---|
| `열림` | **열림** | 색인 열 |
| `닫힘`, `완료`, 글리프 `✅` | **닫힘** | 색인 열. `완료` 와 `✅` 는 스타터의 관례다: *"닫힌 항목은 … 제목에 ✅ 를 달아 남긴다"* (:34), 그리고 그 셈 표는 둘을 닫힘으로 센다 (:2585). |
| `해소` | **해소** | 색인 열; README 의 "해소 칸이 따로 있는 이유" (:415) |
| `결정 대기`, `트리거 대기`, `설계 대기`, `소비자 대기`, `막힘`, `접힘`, `결정됨` | **열림** (한정어, 따로 세지 않는다) | 규칙 넷의 *"결정됨이되 열림"* 과 *"결정을 진척으로 세지 않는 것"* (:102 ~ :106). 규칙 일곱은 막혀 있음 / 트리거 대기 / 결정 대기 를 착수를 면제해 주는 칸의 종류로 든다 (:199). B-25 는 `접힘` 이고(스타터 :13) README 의 "열림 4" 중 하나다 (:323). |

**항목 제목을 읽는 법:**

1. 인라인 코드 스팬을 비우고 `~~…~~` 스팬을 지운다. 백틱 안의 상태는 예시다 — `check-doc-links.py` 가
   링크에 적용하는 것과 같은 원칙이다.
2. **명시적 상태.** 텍스트가 `열림` / `닫힘` / `완료` / `해소` 로 *시작하고*, 그 뒤에 스팬의 끝, 공백, 또는
   `( . , — · :` 중 하나가 오는 각 `**…**` 스팬. 이 경계가 `해소된` 과 `닫힌` 이 상태로 읽히지 않게 한다.
3. **글리프:** 제목 어디든 `✅`.
4. **결과:**
   - 명시적 상태들이 서로 다른 두 칸을 가리키면 *모호한 상태* 발견이다.
   - `✅` 와 명시적 `열림` 또는 `해소` 가 함께 있어도 발견이다.
   - 그 밖에는 명시적 칸이 이긴다.
   - 명시적 상태가 없으면 `✅` 는 닫힘이다.
   - 아무것도 없으면 상태는 **열림**이다. `llm-config-surface` 와 `reasoning-delta-stream` 이 모든 열린
     항목을 이렇게 쓴다.

**상태 기록.** 항목 절 안에서 항목이 아닌 제목이, 같은 경계 규칙 아래에서 상태 단어로 시작하면 그 항목의
상태를 기록한 것이다. 매칭 전에 취소선과 `**` 표식을 없앤다. 예: `### 닫힘 (2026-09-10, #73)` 과
`### 닫힘 (2026-09-10) — 실측했고 …`.

- 절 안의 **마지막** 기록이 이기므로, 되살아난 이력(`### 해소 …` 다음 `### 닫힘 …`)은 순서대로 읽힌다.
- 항목 제목이 마지막 기록과 다른 명시적 상태(단어나 `✅`)를 갖고 있으면 발견이다: "제목은 X, :N 의 기록은
  Y". 정확히 두 사본 중 하나만 고치고 다른 하나를 고치지 않은 것이다.
- `#### 닫음 (…)` 은 기록이 아니다. `닫음` 은 어휘에 없기 때문이다. 그 항목 제목은 이미 닫힘이라고 말한다.

**표제와 색인의 열**은 정확히 `열림` · `닫힘` · `해소`, 색인의 건수 열 셋이다.

- 표제의 괄호는 ` · ` 로 나눈다.
- `<열림|닫힘|해소> <n>` 은 건수다. 표제가 빠뜨린 열은 0 이다.
- `<다른 단어(들)> <n>` 은 발견이다: 모르는 열. `완료 3` 과 `접힘 1` 은 둘 다 실패한다 — 색인에 그런 열이
  없다.
- 숫자 없는 열 이름만 있으면 발견이다.
- 같은 열을 두 번 쓰면 발견이다.
- 그 밖의 텍스트는 한정어이고 무시한다. `(열림 1 · 결정 대기)` 가 이렇게 받아들여진다.

**왜.** `main` 의 항목 제목에 적힌 상태는 전부 굵은 글씨이거나 `✅` 다. 상태 단어가 평문에 나오는 두 자리는
둘 다 함정이다.

- B-15 의 `*(절반 완료 …)*` 는 **열린** 항목에 있다.
- B-6 과 B-14 의 기울임 곁말에는 `완료` 가 들어 있는데, 그 항목들은 어차피 닫혀 있다.

평문을 읽으려면 기울임을 벗기는 규칙이 필요하고, 제목 문장 속의 단어까지 읽게 된다. `완료` 를 알아보면
건수를 하나도 바꾸지 않는 스타터 제목 편집 16건을 아낄 수 있다. 제목이 상태 둘을 말하면 검사는 하나를
고르지 않고 실패한다. T-1 의 `~~열림~~ **닫힘**` 이 이 저장소가 상태 변경을 표시하는 방식이다 — 옛 상태를
긋는다. 긋지 않은 상태 둘은 끝나지 않은 편집이고, 말없이 하나를 고르면 작성자가 무엇을 뜻했는지를 검사가
정하는 것이 된다.

**기각한 대안:**

- **`결정 대기` 를 네 번째 열로 센다.** 색인에 그 열이 없고, 규칙 넷은 결정을 진척으로 세기를 거절한다.
- **`접힘` 에 자기 열을 준다.** 색인이 세 열이므로 범위 밖이다. 열린 질문 3 참조.
- **평문에서 상태 단어를 읽는다.** 위의 이유로 기각.
- **마지막 상태 단어가 이긴다.** 바로 위에서 말한 끝나지 않은 편집을 조용히 받아들이게 된다.

### 4.3 등록부 간 유일성

**결정: 검사한다.** 둘 이상의 등록부에서 읽힌 항목 ID 는 *공유 ID* 발견이다. 스크립트 상수에 이유와 함께
공유로 선언된 ID 만 예외다.

- 오늘 그 목록에는 하나가 있다: `llm-config-surface-open-items.md` 와
  `openai-model-capabilities-open-items.md` 의 `L-1`. 검사보다 먼저 있었다.
- 선언은 스스로 무효가 된다. 충돌이 없어지면 그 항목이 발견이다("지워라").
- 번호 읽기로 읽힌 항목(`1`…`5`)은 이 규칙의 ID 가 아니다 — 늘 등록부와 함께 인용되기 때문이다
  (`interrupt-open-items.md §2`).

**왜.**

- **설계 문서는 ID 를 맨몸으로 인용한다** (`model-capability-binding-round-trip.md:853`
  *"O-1 → backlog `L-13`"*). 이 검사는 선언된 예외를 빼면 맨 ID 가 많아야 한 등록부를 가리킨다는 것을
  보장한다. 독자가 등록부를 열지 않고도 기댈 수 있는 참인 진술이다.
- **모호함이 만들어지는 순간에, 그것을 만든 사람에게서 실패한다.** 다음 충돌은 구체적이다. openai 등록부의
  다음 빈 번호는 `L-2` 인데, `llm-config-surface` 가 이미 갖고 있다(:129). 등록부별 "다음 빈 ID" 가 정확히
  그 충돌을 만든다.
- **기존 충돌은 이미 독자에게 일을 시켰다**(§2.2): 설계 문서 하나가 한 문단을 들였고, 문서 셋이 `L-1` 을
  손으로 한정한다.
- **기존 `L-1` 을 개명하지 않고 공유로 선언하는 이유:** 인용이 맨몸이고 CHANGELOG 와 설계 문서에 흩어져
  있다. 그것을 다시 쓰려면 인용마다 어느 `L-1` 을 뜻했는지 읽어서 정해야 하는데, 그것이 곧 모호함 자체이고
  기계적으로 할 수 없다.

**기각한 대안:**

| 대안 | 기각한 이유 |
|---|---|
| **검사하지 않는다** | 규칙이 산문에만 산다. `translation-tooling-open-items.md` T-1 (*"구조 일치 규칙에는 강제 장치가 없다"*)이 그 끝이 어디인지 보여 주는 이 저장소 자신의 사례이고, openai 등록부의 다음 항목은 아무에게도 알리지 않고 충돌을 되풀이할 것이다. |
| **접두어 소유** (접두어 하나는 등록부 하나의 것) | `L` 을 공유로 선언해야 하고, 그러면 openai 등록부의 `L-2` 가 통과한다 — 가장 일어날 법한 바로 그 충돌이다. |
| **openai 의 `L-1` 을 개명** | 기존 인용이 더 이상 없는 이름을 가리키게 된다(위 참조). |
| **설계 문서에서 맨 인용을 스캔** | 산문을 읽어야 하고, 그래도 인용이 어느 등록부를 뜻했는지 알 수 없다. |

### 4.4 색인 아래의 날짜 문단

**결정.**

- **어느 표가 색인인가:** `docs/backlog/README.md` 에서 펜스 밖에 있고, 헤더 행이 `항목 수`, `열림`, `닫힘`,
  `해소` 를 이름으로 갖는 단 하나의 마크다운 표.
  - 열은 **헤더 이름으로** 찾는다. 앞에 새 열이 생겨도(한때 `출처` 가 그랬다) 아무것도 움직이지 않는다.
  - 맞는 표가 0개이거나 둘 이상이면 발견이다.
- **어느 줄이 행인가:** 구분선 행 바로 뒤에서 `|` 로 시작하는 줄들. 표는 `|` 로 시작하지 않는 첫 줄에서
  끝난다.
- **행을 등록부에 대응시키기:** 첫 칸의 마크다운 링크 대상이 각 행을 `docs/backlog/<file>.md` 로 푼다.
- **커버리지:**
  - 모든 등록부는 정확히 한 행을 갖는다.
  - 모든 행은 존재하는 등록부를 가리킨다.
  - 정수가 아닌 칸은 발견이다.
  - 커버리지 발견은 검사 3 의 일부다 — 행이 없는 등록부는 검사 3 이 말없이 건너뛰는 등록부이기 때문이다.
    README 는 그 실패를 이미 기록한다: *"위 표에 다섯 번째 문서가 빠져 있었다"* (:386 ~ :390). 건수 칸의
    `—` 도 기록한다 (:345).

**날짜 문단이 절대 행으로 읽힐 수 없는 이유.** 문단들은 표가 끝난 **뒤에** 오는 `>` 인용 블록이다. 그들이
인용하는 옛 값은 문장 속 인라인 코드에 있다: `25 | 5` (:321), `5 | 5 | 0 | 0` (:331), `12 | 9 | 3 | 0` (:342),
`5 | 5` (:392). `>` 로 시작하는 줄은 절대 행이 아니고, 문장 속의 파이프도 절대 행이 아니다. 셀프 테스트가
둘 다 고정하므로, 나중에 파이프가 든 모든 줄을 읽도록 "단순화" 하면 트리가 아니라 셀프 테스트가 실패한다.

**기각한 대안:**

- **`## 목록` 제목으로 표를 찾는다.** 헤더 이름 조회는 절 이름 변경과 새 열을 둘 다 견딘다.
- **파일의 모든 `|` 줄을 파싱한다.** 행 모양으로 적힌 노트를 읽게 된다.
- **여섯 열 헤더를 정확히 요구한다.** 열 하나를 더하는 것이 이유 없이 검사를 깨뜨린다.

### 4.5 기계적으로 읽을 수 없는 등록부

**결정: 실패한다.** 면제 장치는 없다.

- `README.md` 를 뺀 모든 `docs/backlog/*.md` 가 등록부다.
  - 번역 접미사가 붙은 파일(`docs_tree.translation_suffix`)은 등록부가 아니다. 요약 줄에서 세기만 하고
    읽지 않는다.
- 등록부에는 건수를 말하는 H1 표제가 있어야 한다.
- ID 로 시작하는 모든 제목은 항목이어야 한다.
- 모든 색인 행은 파싱되어야 한다.
- **모든 실행은 발견이 0건이어도 모든 등록부를 그 셈과 함께 찍는다.** 그러므로 읽히지 않은 등록부는 그것이
  내지 못한 줄로 보인다.

**왜.**

- **이 드리프트가 아무도 모르게 지나간 방식이 침묵이다.** 보고되되 실행을 실패시키지 않는 발견은 아무 뜻도
  없는 초록 실행이다. `check-translation-staleness.py` 가 UNRESOLVABLE 로 그것을 배웠다: 번역 32건 중 19건이
  해석 불가였던 동안 잡은 초록이었다.
- **읽을 수 없는 등록부를 고칠 몫은 언제나 그것을 고치는 사람에게 있다** — 제목 어순을 바꾸거나, 표제를
  더한다. 다른 누구도 막히지 않는다. 그것이 UNRESOLVABLE 을 exit 1 로 만든 논거다.
- **다른 모양으로 쓰인 등록부 하나는 면제가 아니다.** 선언된 읽기로 전부 읽힌다(§4.1).

**기각한 대안:**

- **실패시키지 않고 보고한다.** 위의, 아무 뜻도 없는 초록이다.
- **`structure_exempt` 식의 등록부별 면제.** `main` 에 그것이 필요한 등록부는 없다. 게다가 면제는 그 등록부가
  가진 유일한 검사를 끄는 것이다 — `structure_exempt` 는 다섯 축 중 하나를 끈다.

**남는 사각지대 (docstring 과 README 에 적는다).** ID 가 **아예 없이** 쓴 항목(`## 새 항목 — …`)은 세지
않는다. 작성자가 표제 건수도 그대로 두었다면 두 실수가 서로를 지운다. 검사는 의도가 아니라 제목을 센다.

### 4.6 어느 CI 잡인가

**결정:** **`docs-links`** 의 두 번째 스텝으로, 한 스텝에서 `--self-test` 다음 `--github` 를 돈다(구조
검사의 두 명령 모양). 잡 이름은 그대로이고, 잡 주석에 문단 하나가 붙는다.

**왜.**

- **룰셋은 잡을 이름으로 요구한다(§2.2).**
  - 새 `backlog-registers` 잡은 돌기는 하지만, 누군가 룰셋을 고칠 때까지 **병합을 막지 않는다.** 그러면
    빨간 결과가 병합될 수 있다 — 아무것도 막지 않으면서 빨개질 수 있는 검사다.
  - `docs-links` 를 (예컨대 `docs` 로) 개명하면 필수 컨텍스트가 깨진다. 개명은 그 잡 이름을 적은 산문에서도
    낡는다(`CONTRIBUTING.md` 와 `.ko.md` — 이 작업은 검사 목록 밖을 고칠 수 없다 — 그리고
    `documentation-guide.md` §4).
- **`docs-links` 는 기본 얕은 체크아웃 위의 순수 텍스트 잡이고, 이 검사는 git 을 돌리지 않는다.**
- **`translations` 는 맞는 자리가 아니다.**
  - 이력이 필요해서 `fetch-depth: 0` 으로 체크아웃한다.
  - 주석이 자기 심각도를 번역 신선도로 정의한다.
  - 거기서 백로그 검사가 실패하면 실패한 체크에 엉뚱한 도메인의 이름이 붙는다.
- **두 잡 모두 `setup-python` 을 돌리지 않으므로,** 검사는 다른 검사들처럼 표준 라이브러리만 쓴다.

**기각한 대안:** `translations` 잡, 새 잡, `docs-links` 개명.

## 5. 파일별 구체적 변경

### 5.1 `scripts/check-backlog-registers.py` (신규, 실행 가능, `#!/usr/bin/env python3`)

표준 라이브러리만, 그리고 기존 검사들이 이미 쓰는 것보다 새로운 문법은 쓰지 않는다. 배치 순서:

1. **모듈 docstring.** 구조 검사 방식의 명세다.
   - 압축된 문법 블록 (항목 제목, ID 런, 절, 상태 단어와 경계, 글리프, 기록, 표제 열, 색인 조회).
   - 태스크의 다섯 결정(§4.1 ~ §4.5), 각각 짧은 이유와 함께.
   - CI 배치(§4.6), 검사하지 않는 것(§4.7), 사각지대.
   - 사용법.
2. **상수.**
   - 패턴: `ID`, `ITEM_RUN`, 경계가 붙은 `STATE_WORD`, `TITLE`, `BOLD`, `STRIKE`, `INLINE_CODE`.
   - `COUNT_COLUMNS = ("열림", "닫힘", "해소")`.
   - `CLOSED_SYNONYMS = ("완료",)` 와 글리프 `"✅"`.
   - `READINGS = {"interrupt-open-items.md": NUMBERED}`, 이유는 주석으로.
   - `SHARED_IDS = {"L-1": ("llm-config-surface-open-items.md", "openai-model-capabilities-open-items.md")}`,
     이유는 주석으로.
3. **읽기.** `read_register(name, text, reading) -> Register`, `read_title(line)`, `read_index(text)`.
4. **검사.** `check(docs) -> list[Finding]`, `{relpath: text}` 위의 순수 함수. `main` 과 셀프 테스트가 둘 다
   부른다.
5. **보고.** 요약, 등록부별 셈 줄, 파일별로 묶은 발견, `--github` 애노테이션.
6. **`self_test()`** (§8.1) 와 `main()`.

`scripts/docs_tree.py` 에서 가져오는 것: `ROOT`, `unfence`, `ATX_HEADING`, `translation_suffix`.
`docs_tree.py` 에는 아무것도 더하지 않는다 — 백로그 문법의 소비자는 하나다.

### 5.2 `.github/workflows/build.yml`, 잡 `docs-links`

예시:

```yaml
  # No path filter, and none is wanted: ... (existing paragraph unchanged)
  #
  # The backlog check shares this job for the same reason it could not share `translations`:
  # it reads text and nothing else -- no history, so the default shallow checkout is enough.
  # It is a step here rather than a job of its own because the branch ruleset requires jobs
  # by name; a new job would run without gating anything, and renaming this one would break
  # a required context. The self-test runs first, as in `translations`: on a tree with
  # nothing to catch it is the only thing separating a check that read the registers and
  # found them consistent from one that quietly stopped reading them.
  docs-links:
    ...
      - name: Check relative markdown links and anchors
        run: python3 scripts/check-doc-links.py

      - name: Check backlog registers -- duplicate item IDs, and counts that disagree with the items
        run: |
          python3 scripts/check-backlog-registers.py --self-test
          python3 scripts/check-backlog-registers.py --github
```

### 5.5 `docs/backlog/README.md`: 규칙 일곱이 검사를 얻는다

규칙 일곱의 끝(:227 뒤, `## 항목은 착수하지 않아도 모양이 바뀐다` 앞)에 문단을 더한다. 형제 작업들이 고치는
색인 행(:304 ~ :316)에서 멀리 떨어져 있으므로 편집이 충돌하지 않을 것이다. README 에는 번역본이 없다.
한국어 개요 — README 자신의 목소리로 쓴다:

- **이 규칙의 숫자 절반에는 이제 검사가 있다.** `scripts/check-backlog-registers.py` 가 `docs-links` 잡에서
  세 가지에 실패한다 — 한 등록부 안의 중복 ID, 본문과 어긋난 제목 건수, 본문과 어긋난 위 색인 행.
  이 표에 줄이 없는 등록부, 두 등록부에 같은 ID 도 실패한다(`L-1` 하나는 검사 이전부터 공유되어 스크립트에
  이유와 함께 선언되어 있다 — 새 등록부는 다른 접두어를 쓴다).
- **무엇을 항목으로 읽는가** — ID 로 시작하는 제목(`## L-13 — …`, `### B-19 · B-20 · B-24 — …`) 하나가
  항목 하나다. 상태는 그 제목의 **굵은 글씨**(`**열림**` · `**닫힘**` · `**완료**` · `**해소**`)나 `✅` 에서
  읽고, 아무것도 없으면 열림이다. 항목 안의 `### 닫힘 (…)` 소제목도 상태를 적은 것으로 읽는다.
  `결정 대기` · `트리거 대기` · `접힘` 같은 말은 열림의 한 종류이고 따로 세지 않는다(규칙 넷).
  `interrupt-open-items.md` 만 번호(`## N.`)로 읽는다 — 그 항목들은 번호로 인용된다.
- **아래 날짜 문단은 읽지 않는다.** 표는 헤더에 `항목 수 · 열림 · 닫힘 · 해소` 가 있는 이 파일의 유일한
  표이고, 옛 값을 인용하는 인용 블록은 표가 끝난 뒤에 있으므로 행이 될 수 없다.
- **읽을 수 없는 등록부는 실패한다** — 건너뛰지 않는다. 고칠 방법은 언제나 그 제목 한 줄이다.
- **그리고 이 검사도 이 규칙 아래에 있다.** 검사가 초록이라는 것은 두 사본이 제목의 상태와 **일치**한다는
  뜻이지 그 상태가 **참**이라는 뜻이 아니다(위 "일치는 검증이 아니라 복제다"). 검사가 제목 건수와 어긋난다고
  말하면 틀린 쪽은 건수일 수도 제목의 상태일 수도 있다 — 어느 쪽인지는 여전히 **본문을 읽어서** 정한다.
  검사가 찍은 숫자를 옮겨 적는 것은 셈이 아니다.

새 줄을 **두 번째**에 넣어 기존 "뒤의 둘" 문장이 계속 번역 검사 둘을 가리키게 하고, 문장 하나를 더한다

### 5.7 `CONTRIBUTING.md` (:132 ~ :136) 와 `CONTRIBUTING.ko.md` (:137 ~ :141): 검사 목록만, 같은 커밋

목록이 이미 문서 검사들을 이름으로 적고 있으므로 태스크가 이 편집을 허용한다. 줄을 **네 번째**로 덧붙여,
뒤따르는 산문("The first walks every `*.md` … The other two are about translations" / "첫 번째는 … 나머지
둘은 번역에 관한 것이고")이 자기가 서술하는 줄들에 대해 계속 옳게 읽히게 한다. 소유권 제약에 따라 그 산문은
고치지 않는다.

```bash
python3 scripts/check-backlog-registers.py     # docs/backlog/: duplicate item IDs, and counts that disagree with the items
```

```bash
python3 scripts/check-backlog-registers.py     # docs/backlog/: 한 등록부 안의 중복 ID, 본문과 어긋난 건수
```

`CONTRIBUTING.ko.md` 의 `source_commit` 은 **올리지 않는다.** 두 파일을 함께 건드린 커밋은
`docs_tree.pair_state()` (`translated_in`)가 건너뛰므로 쌍은 신선한 채로 남는다. frontmatter 를 그대로 두면
두 파일의 다른 절을 소유한 형제 #90 과의 충돌도 피한다. 편집 뒤 `check-translation-staleness.py` 와
`check-translation-structure.py` 를 돌린다. 더한 줄은 펜스 안에 있고, 펜스 내용은 비교하지 않는다.

### 5.8 `scripts/docs_tree.py`: 모듈 docstring 의 한 문장 (:3 ~ :10)

"Four scripts walk the same markdown tree -- check-doc-links.py, …, upgrade-translation-links.py" 가
`check-backlog-registers.py` 를 포함한 다섯의 목록이 된다 — 그 스크립트가 이제 `unfence`, `ATX_HEADING`,
`translation_suffix`, `ROOT` 를 가져온다. 목록을 넷으로 두면 docstring 이 그 모듈을 쓰는 스크립트들의 낡은
사본이 된다. 소유권 표 밖의, 따라오는 편집이다. 열린 질문 5 참조.

### 5.9 `CHANGELOG.md` `[Unreleased]`

필수 게이트의 새 실패 모드이므로 동작 변경이다. 구조 검사 항목(:1626 ~ :1667)의 방식으로 쓴다. 예시:

```markdown
### Docs CI: backlog registers are checked for duplicate item IDs and for counts that disagree with the items

- **New check `scripts/check-backlog-registers.py`, a second step of the `docs-links` job** (#88). On
  2026-09-10 two branches registered `L-13` in the same register and git merged both item bodies without a
  conflict; only the count lines collided. It fails on an item ID repeated within a register, on a register
  title (`등록 항목 N건 (…)`) that disagrees with the items, on a `docs/backlog/README.md` index row that
  disagrees with them, on a register with no row, and on an ID read in two registers (`L-1` predates the
  check and is declared shared).
- **It reads headings, never tables or prose.** An item is a heading that starts with its ID; its state is
  the heading's bold `열림`/`닫힘`/`완료`/`해소`, or `✅`, or a nested `### 닫힘 (…)`; nothing means open.
  `interrupt-open-items.md` is read by its `## N.` numbers, which is how it is cited.
- **Two registers had headings reordered so they can be read, and no count changed**: the three §5 group
  headings and the B-21 revival heading in `spring-boot-starter-open-items.md` (which also stops filing
  B-21 under 해소), and `### T-1 (원문)` in `translation-tooling-open-items.md`.
- **`--self-test` runs first**: it breaks the real tree one way at a time (a duplicated ID, a wrong title, a
  wrong row) and switches each reading rule off in turn against a synthetic register.
```

### 5.10 바꾸지 않는 것

- **건수 정정 없음.** 실측된 것이 없다(§2.2). 구현자의 최종 실행이 다르게 나오면 본문에서 정정하고, 정정마다
  전후 숫자와 함께 PR 본문에 나열한다.
- Java 나 Gradle 파일 없음. 그러므로 `checkAll` 은 필요 없다.
- **`docs/design/documentation/` 아래 설계 문서 없음.** 수용 기준 4 는 docstring 과 README 를 이름으로 든다.
  세 번째 자리는 드리프트할 수 있는 또 하나의 사본이고, 그것이 이 검사가 잡으려고 존재하는 것이다.

종료 코드:

- `0` 은 발견 없음. `--self-test` 에서는 모든 케이스가 명세대로 동작했다는 뜻이다.
- `1` 은 발견이 하나라도 있거나, 셀프 테스트 케이스가 실패했거나 구성할 수 없었다는 뜻이다.

git 을 쓰지 않는다. 경로는 `docs_tree.ROOT` 에서 푼다.

**발견.** 각 발견은 `Finding(kind, path, line, text)` 다. 모든 종류가 하드 실패다.

| `kind` | 언제 |
|---|---|
| `duplicate-id` | 한 등록부에서 ID 가 두 번 읽힌다(두 줄 모두 이름을 댄다). 번호 읽기(`## 3.` 두 번)도 포함한다. |
| `title` | 다음 중 하나: `등록 항목 N건 (…)` 를 담은 H1 이 없음; N ≠ 항목 수; 열 ≠ 셈; 모르는 열; 숫자 없는 열 이름; 두 번 쓴 열. |
| `index` | 다음 중 하나: 색인 표가 0개 또는 2개; 링크 없는 행; 없는 파일이나 등록부가 아닌 것을 가리키는 행; 중복 행; 행이 없는 등록부; 정수가 아닌 칸; 칸 ≠ 셈. |
| `state` | 모호한 제목 상태, 명시적 열림이나 해소와 함께 있는 `✅`, 또는 마지막 기록과 다른 제목 상태. |
| `unread-heading` | 제목이 ID 로 시작하지만 항목 제목이 아니다. |
| `shared-id` | ID 가 두 등록부에서 읽히는데 선언되지 않았거나, 선언된 공유 ID 가 더 이상 공유되지 않는다. |
| `reading` | 선언된 읽기가 없는 파일이나, ID 항목 제목을 가진 파일을 가리킨다. |
| `layout` | `docs/backlog/` 나 그 `README.md` 가 없다. 환경이 아니라 내용이므로 실패한다. |

**내부 모양.** 구조 검사의 `Structure` 와 `Finding` 처럼 `__slots__` 를 쓰는 평범한 클래스다.

- `Item(ids, line, level, heading_state, records)` — `heading_state` 는 `None`(명시적 상태 없음), `열림`,
  `닫힘`, `해소` 중 하나이고, `records` 는 `(line, state)` 의 리스트다.
- `Register(name, reading, title_line, title_n, title_counts, title_qualifiers, items, tally)`.
- `IndexRow(line, target, cells)`.

**출력.** 다른 검사들을 따른다: 요약이 먼저, 그다음 파일별로 묶은 발견.

```
checked 11 register(s), 11 index row(s), 83 item(s)
  architecture-review-open-items.md          8  (열림 2 · 닫힘 6 · 해소 0)
  config-value-expansion-open-items.md       2  (열림 2 · 닫힘 0 · 해소 0)
  interrupt-open-items.md                    5  (열림 2 · 닫힘 3 · 해소 0)   numbered reading
  ...
declared: 1 shared ID (L-1), 1 numbered reading, 0 translation file(s) skipped

every register's title and index row agree with its items
```

발견이 있을 때:

```
docs/backlog/llm-config-surface-open-items.md
  :786  duplicate-id    L-13 is also the item heading at :746 -- give the later item the next free ID
  :1    title           등록 항목 16건 but 17 items are read (열림 13 · 닫힘 4)
docs/backlog/README.md
  :313  index           llm-config-surface-open-items.md row says 16 | 12 | 4 | 0, items read 17 | 13 | 4 | 0
```

`--github` 는 발견마다 `::error file=<path>,line=<n>::<text>` 를 더한다. `line=` 은 파일 단위로만
애노테이션하는 기존 검사들에서 조금 벗어나는데, 여기의 모든 발견은 줄(제목, 표제, 행)을 갖고 있으므로
정당하다. 모든 발견이 잡을 실패시키므로 독자가 여는 것은 완전한 콘솔 출력이고, GitHub 이 애노테이션을
잘라도 아무것도 가려지지 않는다.

| 실패 모드 | 처리 |
|---|---|

| 색인 행 없이 새 등록부를 더한다 (README :386 ~ :390) | `index` (커버리지). |
| 구분자 없이 항목 제목을 쓴다 (`## L-16 title`) | `unread-heading`. |
| ID 없이 항목을 쓰고, 표제 건수도 그대로 둔다 | **잡히지 않는다** (두 실수가 상쇄). 사각지대로 문서화한다. |
| 소제목이 우연히 상태 단어로 시작한다 (`### 해소 조건`) | 기록으로 읽힌다. 결과는 그 줄을 이름으로 대는 시끄러운 `title`/`state` 발견이고, 고치는 법은 문구를 바꾸는 것이다. 문법의 알려진 날카로운 자리 하나로, docstring 에 적는다. |
| 옛 단어를 긋지 않고 상태를 바꾼다 | `state` (모호). |
| 제목은 고쳤는데 `### 닫힘` 기록은 안 고쳤다, 또는 그 반대 | `state` (충돌). |
| openai 등록부의 다음 항목이 `L-2` 를 가져간다 | `shared-id`, `llm-config-surface:129` 를 이름으로 댄다. |
| 선언된 `L-1` 충돌이 개명으로 없어진다 | `shared-id` (낡은 선언): 항목을 지운다. |
| 인터럽트 등록부가 ID 로 바뀐다 | `reading` (낡은 선언): 항목을 지운다. |
| 색인이 재구성된다 (절 개명, 열 추가) | 영향 없음: 표는 건수 열 네 이름으로 찾는다. 맞는 표가 둘이 되면 `index`. |
| 날짜 노트가 행을 인용하거나, 장래의 노트가 인용 블록 속 행으로 쓰인다 | 절대 읽지 않는다. 셀프 테스트가 고정한다. |
| 읽기 규칙이 나중에 코드에서 "단순화" 되어 빠진다 | 그 규칙을 끄는 셀프 테스트 케이스가 더 이상 차이를 보이지 못하므로 셀프 테스트가 실패한다(§8.1). |
| 셀프 테스트의 변조 대상이 사라진다 (예: 항목이 2개 이상인 등록부가 없음) | 그 케이스는 "구성할 수 없음" 으로 실패한다. 절대 건너뛰지 않는다. |
| 인코딩 문제 | 다른 검사들처럼 `errors="replace"` 로 읽는다. 망가진 제목은 조용한 것이 아니라 시끄러운 건수나 읽기 발견으로 드러난다. |
| 얕은 클론, 또는 git 이 아예 없음 | 무관: 이력을 쓰지 않는다. |
| 백로그 번역본(`*.en.md`)이 생긴다 | 등록부가 아니다. 요약 줄에서 센다. |

## 8. 테스트 전략

### 8.1 `--self-test`: CI 에서, 검사 앞에

셀프 테스트는 선례의 틀을 따른다: 코퍼스를 고정하고 한 번에 하나만 바꾸며, 절대값이 아니라 변조 없는
기준선과의 **차이**를 센다. 그러므로 이미 드리프트가 있는 트리는 셀프 테스트를 초록으로 남기고, 실제 트리에
대한 판정을 가진 본 실행이 그것을 한 번 보고한다. 발견은 `(kind, path)` 의 멀티셋으로 비교한다. 줄 번호는
뺀다 — 줄 하나를 끼우면 뒤의 모든 줄이 밀리기 때문이다.

**A. 필수 실패 모드 셋, 각각 실제 트리에서.** 대상은 이름이 아니라 규칙으로 고르고, 대상을 찾지 못한
케이스는 실패한다.

| 케이스 | 변조 (메모리 안) | 더해져야 하는 것 |
|---|---|---|
| 중복 ID | 단일 ID 항목 제목이 2개 이상인 첫 등록부(정렬순)에서, 둘째 항목의 ID 를 첫째 것으로 바꾼다. 건수는 그대로다. 오늘: `architecture-review`, R-7 → R-1. | `duplicate-id`, 그 밖엔 없음 |
| 틀린 표제 합계 | 표제가 있는 첫 등록부: `등록 항목 N건` → `N+1`. | `title` |
| 틀린 표제 분할 | 같은 등록부: 첫 번째 0 아닌 열에서 두 번째 열로 1 을 옮긴다(합계 불변). | `title` |
| 틀린 색인 합계 | 첫 색인 행: `항목 수` + 1. | `index` |
| 틀린 색인 분할 | 같은 행: `열림` 과 `닫힘` 칸을 맞바꾼다. | `index` |
| 없는 행 | 첫 색인 행을 지운다. | `index` |

**B. 읽히지 않아야 하는 것 (실제 트리).**

| 케이스 | 변조 | 더해져야 하는 것 |
|---|---|---|
| 날짜 노트는 행이 아니다 | 색인 표 바로 아래에 `> \| [\`x.md\`](x.md) \| 출처 \| 99 \| 99 \| 0 \| 0 \|` 와, 틀린 숫자로 `` `34 \| 4 \| 26 \| 4` `` 를 인용하는 산문 줄을 끼운다. | 없음 |
| 등록부 간 | (자기 색인 행을 가진) 합성 등록부를 더하고 `## R-1 — …` 을 넣는다. | `shared-id` |
| 낡은 공유 선언 | openai 등록부의 `L-1` 제목을 지운다(표제도 어긋날 것이다; 더해진 발견 중에 `shared-id` 가 있음을 단언). | `shared-id` |
| 낡은 번호 읽기 | `interrupt-open-items.md` 에 `## IR-1 — x · **열림**` 을 더한다. | `reading` |

**C. 각 읽기 규칙이 하중을 받는다.** 합성 등록부와 그 색인 행을 실제 코퍼스에 더한다. 모든 규칙은 읽기가
받는 스위치다(기본 켬). 각 케이스는 규칙 **하나**를 끄고, 규칙을 켰을 때는 없던 발견을 합성 등록부가 이제
낸다고 단언한다. 누군가 코드에서 규칙을 지우면 그것을 꺼도 아무것도 바뀌지 않으므로 케이스가 실패한다.
합성 등록부는 명세된 문법 아래에서 깨끗하게 읽힌다. 예시:

```markdown
# 셀프 테스트 — 등록 항목 8건 (열림 3 · 닫힘 4 · 해소 1)
## Z-1 — 상태를 적지 않은 항목
### 해소된 까닭
## Z-2 — 상태가 바뀐 항목 · ~~**열림**~~ **닫힘 (날짜)**
## Z-3 — 곁말은 읽지 않는다 *(절반 완료)*
## Z-4 — 하위 제목이 닫는다
### 닫힘 (날짜)
## Z-5 · Z-6 — 한 제목에 둘 ✅
## Z-7 · U-8 — 코드 안의 `**닫힘**` 은 예시다 · **열림 · 결정 대기**
## Z-8 — 전제가 없던 항목 · **해소**
### 원문 — Z-1
```

Z-2 는 **굵은** 단어를 일부러 긋는다. `main` 의 T-1 은 평문 단어를 긋는데(`~~열림~~ **닫힘**`), 굵은 글씨만
읽는 규칙에서 그은 평문 단어는 절대 읽히지 않는다. 그러므로 오늘의 코퍼스에서 취소선 제거는 굵은 글씨만
읽기와 중복이다. 그래도 남기는 것은 그것이 `~~**열림**~~` 형태를 지키기 때문이고, 그것을 보일 수 있는 것은
합성 제목뿐이다.

| 끈 규칙 | 틀린 읽기와 그것이 깨는 것 |
|---|---|
| 취소선 제거 | Z-2 가 열림과 닫힘을 읽는다 → `state` |
| 굵은 글씨만 상태 단어 | Z-3 가 완료를 읽는다 → `title` (열림 2 · 닫힘 5) |
| 인라인 코드 비우기 | Z-7 이 닫힘과 열림을 읽는다 → `state` |
| 상태 기록 | Z-4 가 열림으로 읽힌다 → `title` |
| 단어 경계 | `### 해소된 까닭` 이 Z-1 을 해소로 기록한다 → `title` |
| 같은 접두어 ID 런 | Z-7 · U-8 이 항목 둘로 읽힌다 → `title` (9) |
| `(원문)`/읽지 않음 규칙 (`### 원문 — Z-1` 은 ID 가 앞서지 않고, 항목이 아니다) | *스위치가 필요 없다.* 대신 두 번째 변조가 `### Z-1 (원문)` 으로 어순을 바꾸고, `unread-heading` 이 더해져야 한다. |
| 표 줄만 행 (`>` 줄을 행으로 읽기) | 케이스 B 의 노트 변조와 함께 적용한다: 인용 블록 속 노트 행이 그 등록부의 두 번째 행이 된다 → `index` |
| 번호 읽기에서 `## 0.` 제외 | (셀프 테스트용으로 선언한) 합성 번호 등록부에 `## 0.` 이 있으면 하나를 더 센다 → `title` |

**출력**은 구조 검사의 셀프 테스트 방식이다: 케이스마다 변조와 그것이 더한 발견을 이름으로 대는 `ok` 또는
`FAIL` 한 줄, 그다음 *"for context, the real tree has N finding(s) right now -- the main run owns that
verdict"*, 그다음 맺는 문장. 실패했거나 구성할 수 없는 케이스가 있으면 exit 1.

   필요하다.
3. **`접힘` 이 자기 색인 열을 가져야 하는가?** 용어표는 그것을 상태로 정의한다(`translation-glossary.md:162`
   *"더 큰 항목 안으로 들어갔다"*). B-25 가 쓰는 뜻은 그것이 아니고, B-25 는 열림으로 센다. 색인이 세
   열이므로 검사는 그것을 열림으로 센다. 그것을 바꾸는 것은 README 의 결정이고, #88 밖이다.
4. **절 소계**(§4.7)는 검사하지 않는다. 그것이 백로그 항목이어야 하는가, 그렇다면 어느 등록부인가? 맞는
   것이 없다: `translation-tooling-open-items.md` 는 번역 도구에 관한 것이다. 권고: 검토자가 등록부를 지목하지
   않는 한 `build/deviations.md` 에만 기록한다.
5. **`scripts/docs_tree.py` 는 이 작업의 소유권 표에 없다.** §5.8 의 docstring 문장은 거기서 가져오는 것의
   결과다. 권고: 편집하고, PR 본문에 이름을 댄다. 대안 — 가져오지 않고 `unfence` 를 새 스크립트에 복사하기 —
   는 그 모듈이 막으려고 쓰인 바로 그 드리프트다.
6. **`L-1` 을 개명하지 않고 공유로 둔다**(§4.3). 오케스트레이터는 개명을 선호할 수도 있다. 권고: 선언을
   유지한다 — 개명하면 인용이 더 이상 없는 이름을 가리키게 된다.
7. **선언된 읽기가 사는 자리.** 스크립트 상수에 있다(§4.1, §4.3). 대안은 `structure_exempt` 처럼 등록부 자신의
   frontmatter 다. 권고: 스크립트 상수. 각각 하나씩이고, 등록부에는 오늘 frontmatter 가 없다. 키 하나를 위해
   frontmatter 를 더하면 모든 등록부에 두 번째 파서가 생기고, mkdocs 가 빌드하지도 않는 디렉토리에 YAML
   유효성 질문(T-3 의 것)이 생긴다.

## 10. 구현이 설계와 갈린 곳

구현하면서 설계와 달라진 자리를 전부 적는다. 출처는 넷이다 — 설계 검토의 비차단 지적(**검토**), 작업을

측정은 설계를 그대로 재현했다. §5.3 ~ §5.4 편집 전에는 83 이 아니라 77 항목이 읽혔다 — 스타터 28(열림 3 ·
닫힘 22 · 해소 3)이 표제 34 와 어긋났고, `unread-heading` 은 정확히 둘(:2407, :134)이었다. 편집 후 83 항목,

**빌드 검토 1** 이 차단 결함 하나를 찾았다 — 셀프 테스트의 대상 선택이 평범한 드리프트에서 빨개졌고, CI 스텝이
