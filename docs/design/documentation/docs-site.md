## 2. 레이아웃: 폴더 분리가 아니라 접미사

`docs/ko/` + `docs/en/` 로 가르는 폴더 방식은 채택하지 않았다. 결정 시점에 저장소에 걸려 있던 것은 이랬다.

| 깨지는 것 | 개수 |
|-----------|------|
| 문서 간 상대 링크 | 946 |
| Java Javadoc 안의 `docs/...` 참조 | 105 |
| `CLAUDE.md` 의 `@docs/...` 참조 | 4 |

폴더 방식은 이 1,055개를 전부 고쳐야 하고, 상대 경로는 문자열 치환으로 고칠 수 없다. 접미사 방식은
**정본 파일이 한 칸도 움직이지 않는다.**

```
docs/features/tool/tool-development-guide.md       ← 한국어 정본 (경로 불변)
docs/features/tool/tool-development-guide.en.md    ← 영어 번역
```

`mkdocs-static-i18n` 이 이 규약을 기본 지원한다.

## 3. 사이트 루트의 기본 언어는 한국어

정본 언어와 사이트 기본 언어는 원래 별개 결정이고, GitHub 유입을 생각하면 루트가 영어인 쪽이 선호였다.
spike 로 확인해 보니 **그쪽은 빌드가 되지 않는다.**

`mkdocs-static-i18n` 의 접미사 모드에서 무접미사 파일은 **기본 로케일의 것**이고, 기본 로케일은 언제나
사이트 루트에 빌드된다. 즉 "무접미사 = 한국어" 와 "기본 로케일 = 영어" 는 동시에 성립할 수 없다.
`default: true` 를 `en` 에 주면 두 `index.md` 가 같은 자리를 다투고 빌드가 끊긴다.

```
Exception: Conflicting files for the default language 'en':
choose either 'index.md' or 'index.md' but not both
```

영어 루트를 살리려면 정본 전부에 `.ko` 접미사를 붙여야 하는데, 그것은 §2 가 접미사를 고른 이유(정본이
움직이지 않는다)를 스스로 무르는 일이다.

| URL | 내용 | 파일 |
|-----|------|------|
| `/` | 한국어 (정본) | 무접미사 |
| `/en/` | 영어 (번역) | `.en.md` |

번역이 없는 문서는 **404 가 아니라 `/en/` 아래에 한국어 정본이 그대로 서빙된다** — 별도 설정이 아니라
`fallback_to_default` 의 기본값이다. 번역이 일부만 있어도 사이트가 늘 온전하다는 뜻이다.

루트가 한국어인 대가(영어권 독자가 한 번 더 클릭한다)는 언어 스위처와 `README.md` 의 영어 링크로 갚는다.

## 4. 한국어 검색 — `separator` 는 실측으로 정했다

착수 전 가정("형태소 분석이 없으니 한국어 검색은 안 된다")은 절반만 맞았다.

1. Material 의 한국어 로케일은 lunr 파이프라인을 비워 둔다 — stemmer 도, stopword 필터도, **trimmer 도** 없다
2. Material 은 모든 질의어 뒤에 `*` 를 붙인다. 즉 **모든 검색은 접두 검색**이다
3. 한국어 조사는 접미사이므로 2 가 1 을 구제한다 — `세션` 이 `세션을`·`세션이`·`세션은` 을 모두 잡는다

문제는 다른 데 있었다. trimmer 가 없어 **구두점이 토큰에 붙어 있고**, 접두 검색은 단어가 토큰의 맨 앞에
있을 때만 잡는다. 기본 `separator` 로 잰 결과다.

| 질의 | 기본 `[\s\-]+` | 튜닝 후 |
|------|----------------|---------|
| `이터레이션` | **0** — 문서에 단독으로 없고 `Iteration(이터레이션)` 으로만 나온다 | 5 |
| `세션` | 12 | 17 |
| `수명` | 6 | 9 |
| `execution` | 3 | 6 |

괄호·쉼표·따옴표 같은 구두점을 구분자에 넣어 해소했다. **`.` 은 일부러 넣지 않는다** — 넣으면
`aimon.llm.provider` 와 `at.aimon.core.agent` 가 조각난다. 현재 정규식의 정본은 `mkdocs.yml` 의 `search`
플러그인 설정과 그 위의 주석이다.

> 순정 lunr 로 먼저 실험했을 때는 영어 Porter stemmer 가 질의어만 어간화해 `livesession` → `livesess` 로
> 깨지는 것으로 나왔다. **Material 에서는 일어나지 않는다** — Material 은 `pipeline` 에 없는 함수를 색인·검색
> 양쪽에서 제거한다. 순정 lunr 의 기본값을 Material 의 동작으로 옮겨 적으면 안 된다.

## 5. 내비게이션 — `nav:` 를 쓰지 않는다

`mkdocs.yml` 에 `nav:` 를 두면 `docs/README.md` 의 인덱스와 **같은 목록을 두 벌 유지**하게 된다. 새 문서를
추가한 사람이 한쪽만 고치면 사이트나 인덱스 한쪽에서 사라진다.

`nav:` 를 생략하면 MkDocs 가 디렉토리 트리에서 내비게이션을 만든다. 알파벳순이라 손으로 고른 순서보다
못하지만, **손으로 유지하는 목록이 `docs/README.md` 하나**로 남는다. `awesome-pages` 같은 플러그인은
`.pages` 파일로 순서를 되찾아 주지만 유지 대상이 하나 더 느는 일이라 택하지 않았다.

## 6. 앵커 — GitHub 과 사이트가 같은 슬러그를 만든다

`toc` 확장의 `slugify` 를 `pymdownx.slugs.slugify(case=lower)` 로 맞췄다. 그래서 GitHub 에서 생기는 앵커가
사이트에서도 글자 그대로 같고, GitHub 의 슬러그 규칙을 모델링한 `scripts/check-doc-links.py` 가 사이트의
앵커까지 함께 지킨다 — 게이트를 하나 더 만들지 않고 범위가 넓어졌다.

## 7. `docs/` 밖을 가리키는 링크

문서는 두 표면에서 읽힌다. GitHub 에서는 `../../../modules/.../ReadTool.java` 가 맞는 링크이고, 사이트에는
`modules/` 가 없으므로 죽은 링크다. 원본을 고치면 사이트를 살리는 대신 GitHub 을 깨뜨린다.

그래서 원본은 상대 경로 그대로 두고, `scripts/mkdocs_github_links.py` 훅이 **`docs_dir` 를 벗어나는 링크만**
렌더 시점에 GitHub URL 로 바꾼다. `docs/` 안에 머무는 링크는 건드리지 않으므로(예외 하나는 §7.2) MkDocs 의
링크 해석과 `.en.md` 매핑이 그대로 동작하고, 덕분에 CI 가 `mkdocs build --strict` 를 쓸 수 있다. 플러그인 없이 MkDocs
내장 `hooks:` 로 처리했다.

> 훅을 처음 쓸 때 인라인 코드를 보호하려고 줄을 코드 스팬 기준으로 잘라 붙였더니,
> ``[`ReadTool`](...)`` 처럼 **링크 텍스트가 백틱인 링크가 반토막**나서 199개 중 54개만 바뀌었다. 자르지 않고
> **위치로 건너뛰도록** 고쳤다.

### 7.1 훅이 건드리지 않는 것 — 사이트에 빌드되는 디렉토리를 가리키는 링크

훅이 "`docs/` 안에 머무는 링크는 건드리지 않는다" 고 할 때, MkDocs 가 풀지 못하는 링크가 하나 그 안에 남는다 —
**사이트에 빌드되는 디렉토리**를 가리키는 링크다(`../features/`, `tool/`). GitHub 에서는 트리 화면이 열리지만
사이트에는 디렉토리의 페이지가 없다. MkDocs 는 `unrecognized relative link … left as is` 를 **INFO** 로 찍고
`href` 를 그대로 두며, `--strict` 는 WARNING 만 실패로 바꾸므로 빌드는 초록이다. 2026-10-05 에 실측했을 때
그런 링크가 7개 파일에 41개 있었고 빌드는 그 INFO 를 46줄 찍었다(두 로케일로 빌드되는 `design/README.md` 의
다섯 개가 두 번씩).

**그 링크는 훅이 아니라 `scripts/check-doc-links.py` 가 실패시킨다.** 훅이 GitHub 트리 URL 로 바꿔 줄 수도
있었지만 그러지 않았다 — 사이트 안에 있는 내용을 읽으러 온 사람을 사이트 밖으로 내보내게 되고, 디렉토리에
`README.md` 가 있으면 그것이 곧 그 디렉토리의 페이지이므로 원본에서 그렇게 쓰는 편이 두 표면 모두에서 맞다.

실패하는 것은 **링크가 놓인 파일과 대상 디렉토리가 둘 다 사이트에 빌드되는 경우**뿐이다. "빌드된다" 는
`docs_dir` 안에 있고 `exclude_docs` 가 이름 붙인 디렉토리 아래가 아니라는 뜻이다. 나머지 디렉토리 링크는
계속 받아들인다 — 읽히는 모든 표면에서 무언가가 그것을 열어 주기 때문이다.

| 링크가 놓인 파일 | 대상 디렉토리 | 결과 | 누가 여는가 |
|-----------------|--------------|------|------------|
| 사이트 페이지 | 사이트에 빌드됨 | **실패** | 아무도 — 사이트에 디렉토리의 페이지가 없다 |
| 사이트 페이지 | `docs/` 밖 (`../../modules/aimon-core/`) | 통과 | 훅이 GitHub 트리 URL 로 바꾼다 |
| 사이트 페이지 | `exclude_docs` 아래 (`../backlog/`) | 통과 | 훅이 GitHub 트리 URL 로 바꾼다 |
| 사이트 페이지가 아님 (저장소 루트 `README.md`, `.claude/**`, `docs/backlog/**`) | 어디든 | 통과 | GitHub 의 트리 화면 — 그 파일은 GitHub 에서만 읽힌다 |

실패 메시지는 무엇을 쓸지 말한다 — 그 디렉토리의 `README.md`, `*.en.md` 에서는 번역본이 있을 때
`README.en.md`. 디렉토리에 README 가 없으면 **만들라고 하지 않는다**: 색인 페이지를 둘지는 글쓴이가 정할
일이므로, 그 안의 페이지를 가리키거나 링크를 빼라고만 한다. 41개 중 31개가 이 경우였다 —
`features/README.md` 의 절 제목 열두 개는 바로 아래 표가 그 디렉토리의 문서를 전부 싣고 있어 링크를 뺐고,
`design/backlog/` 는 `design/README.md` 의 해당 절을, `migration/` 과 `project/` 는 `docs/README.md` §6 을
가리키게 했다.

`migration/` 과 `project/` 의 넷(`overview/features.md` 와 `.en.md` 에 둘씩)은 그 뒤 같은 날 두 디렉토리에
`README.md` 가 생기면서 그 색인으로 다시 옮겼다. 두 README 에는 `.en.md` 가 없다 — 그 디렉토리들이 아직 번역
대상이 아니어서이고(`documentation-guide.md` §5.1), `features.en.md` 의 링크는 `README.md` 를 가리켜 `/en/`
에서 한국어 색인이 나온다.

**"빌드된다" 를 두 곳에서 읽는다.** 훅은 MkDocs 가 파싱한 `exclude_docs`(pathspec)를 받고, 검사는 받을 수
없다 — `docs-links` 잡은 체크아웃 직후 `pip install` 없이 돌므로 `yaml` 도 `pathspec` 도 없다. 그래서
`scripts/docs_tree.py` 의 `site_tree()` 가 `mkdocs.yml` 을 정규식으로 읽고, gitignore 엔진 없이 정확히 맞출
수 있는 모양 하나 — 앞에 슬래시가 붙은 디렉토리(`/backlog/`) — 만 받는다. 그 밖의 패턴(깊이를 가리지 않는
`backlog/`, 와일드카드, `!` 부정, 파일 패턴)은 반쯤 이해하는 대신 **거부**하고, 링크 검사는 그 이유를 말하며
빨개진다. 두 읽기가 어긋나지 않게 하는 것은 이 문단이 아니라 훅의 `on_config` 다 — 사이트를 빌드할 때마다
`docs_dir` 아래 모든 디렉토리에 대해 두 답을 비교하고, 하나라도 다르면 빌드를 멈춘다.

### 7.2 번역을 건너는 fragment — 같은 자리의 제목으로 옮긴다

§7 의 "`docs/` 안에 머무는 링크는 건드리지 않는다" 에는 예외가 하나 있다. 번역이 없는 페이지는 `/en/` 에서
한국어 원문 그대로 나오는데, 그 안의 `guide.md#matcher-문법` 은 mkdocs-static-i18n 이 `guide.en.md` 로
보낸다(`Files.get_file_from_path` 가 빌드 로케일의 파일을 먼저 고른다). 거기에는 그 id 가 없다. 링크는
GitHub 과 한국어 사이트에서 맞으므로 원본이 틀린 것이 아니고, `check-doc-links.py` 는 정본에 대고 확인해
통과시켰다. 2026-10-06 에 두 방법으로 쟀다(소스 스캔, 빌드된 사이트의 fragment `href` 23,379개 전수) —
**3개 파일의 6개**, 전부 `/en/` 쪽이다.

**훅이 fragment 를 옮긴다.** 링크가 가리킨 파일과 빌드가 내놓는 파일이 다르면, 정본에서 그 fragment 가
몇 번째 제목인지 찾아 번역본의 **같은 자리 제목의 id** 로 바꾼다. 자리가 대응을 뜻하는 것은 구조 검사가
쌍의 제목 수 · 레벨 · 순서를 맞춰 두기 때문이다. 고른 것과 버린 것:

- **검사만 실패시키기** — 버렸다. 고칠 방법이 영어 쪽에 한국어 `<a id>` 를 심는 것뿐인데, 링크가 늘 때마다
  번역본에 번역되지 않는 줄이 쌓인다(이미 둘 있었다)
- **그 페이지들을 번역하기** — 버렸다. `design/` 은 번역 대상이 아니고(§8), 링크 여섯 때문에 문서 셋을
  번역할 일도 아니다
- **로케일을 묻지 않는다.** 훅은 "이 경로를 이 빌드가 어느 파일로 내놓는가" 만 묻는다. 한국어 빌드에서는
  같은 파일이 돌아와 아무 일도 없고, `.en.md` 가 정본의 한국어 앵커를 가리키는 반대 방향(현재 0건)도 같은
  한 줄로 옮겨진다
- **id 는 사이트의 것을 쓴다.** 두 파일을 빌드와 같은 `markdown_extensions` 로 렌더해 `toc_tokens` 에서
  읽는다. `docs_tree.slug` 로 계산하지 않는 이유는 실측이다 — 144개 페이지 중 40개에 사이트 id 와 그
  slug 가 다른 제목이 있고(코드 스팬 안의 `_` 유지, 반복 제목의 `_1`, 태그로 읽혀 사라지는 `<…>`, 이모지가
  남기는 맨 앞 `-`), 7개는 제목 수부터 다르다. fragment 는 정본의 사이트 id 와 **글자 그대로** 맞아야 옮긴다 — 맞지 않으면 한국어
  사이트에서도 이미 죽은 링크이고, 영어에서만 살리면 그 사실이 가려진다
- **추측하지 않는다.** 두 파일의 제목이 어긋나면(수가 다르거나 레벨이 하나라도 다르면) 링크를 그대로 둔다

| 경우 | 훅 | `check-doc-links.py` |
|------|----|----------------------|
| fragment 가 제목이고 쌍의 제목이 맞는다 | 옮긴다 | 통과 |
| 쌍의 제목이 어긋난다 (번역이 뒤처졌거나, 구조 검사가 잡을 불일치) | 그대로 두고 INFO | **보고만** (`--github` 이면 경고 주석) |
| 번역본에 같은 이름의 앵커가 있다 (`#api`, 양쪽에 둔 `<a id>`) | 그대로 둔다 — 풀린다 | 통과 |
| 정본에만 있는 손으로 쓴 `<a id>` | 그대로 둔다 | **실패** — `<a id>` 를 번역본에도 둔다 |
| 반복된 제목의 둘째 이후 (`#설정-1`) | 그대로 둔다 — 사이트의 id 는 `_1` 이다 | **실패** |
| 사이트만 제목을 하나 더 본다 | 그대로 두고 **WARNING** — `--strict` 가 멈춘다 | 통과 (못 본다) |

"보고만" 은 번역 낡음과 같은 판단이다 — 뒤처진 번역이 빌드를 깨면 정본 수정이 미뤄진다. 링크 검사는 얕은
클론에서 돌아 쌍이 현재인지 알 수 없으므로 둘을 가르지 않고, 현재인 쌍의 불일치는 구조 검사가 실패시킨다.

**제목을 두 곳에서 읽는다.** 검사는 `pip install` 없이 돌아 `docs_tree.headings_of` 로 읽고, 훅은 사이트의
렌더를 읽는다. 표의 마지막 줄이 그 틈이고, 훅을 처음 돌린 날 실제로 걸렸다 — 훅 가이드의 한 문단이 줄바꿈
뒤 `#<n>, handler …` 로 시작했는데, Python-Markdown 은 `#` 뒤에 공백이 없어도 제목으로 읽어 한국어 사이트에
H1 이 하나 더 있었다(GitHub 과 검사에는 없다). 그래서 훅은 자기 읽기로 어긋났을 때 검사의 읽기를 다시
묻고, 검사가 "맞는다" 고 하면 WARNING 을 낸다: 그것은 뒤처진 번역이 아니라 검사가 통과시킨 죽은 링크다.

훅의 `--self-test` 는 `mkdocs.yml` 을 `INHERIT` 한 작은 두 로케일 사이트를 임시 디렉토리에 빌드해 빌드된
페이지의 `href` 를 읽는다 — i18n 플러그인과 `toc` slugify 를 베끼지 않으려는 것이다. `docs.yml` 이 실제
빌드 앞에서 돌린다.
